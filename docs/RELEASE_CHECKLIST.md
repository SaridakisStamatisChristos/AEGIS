## 1. Release identity

- [ ] Version is valid SemVer.
- [ ] Candidate commit is contained in `main`.
- [ ] `CHANGELOG.md` contains the release entry.
- [ ] Python SDK version matches the release version.
- [ ] TypeScript SDK version matches the release version.
- [ ] UI version matches the release version.
- [ ] npm lockfiles were generated by npm, not hand-edited.
- [ ] No protocol/schema version was changed accidentally as part of an application-only patch.

## 3. Registry-publishing preflight

### PyPI

- [ ] project/publisher exists.
- [ ] Trusted Publishing/OIDC or the approved publish credential is configured.
- [ ] workflow identity matches the publisher configuration.
- [ ] target version does not already exist unless the retry is intentionally idempotent.

### npm

- [ ] package/publisher exists.
- [ ] trusted publishing/OIDC or the approved publish credential is configured.
- [ ] package scope/access is correct.
- [ ] target version does not already exist.

If a registry is intentionally unavailable, mark that distribution channel **PENDING** rather than pretending the entire release is green.

## 4. Tag

- [ ] Exact release SHA recorded.
- [ ] Tag created on that SHA.
- [ ] Tag pushed.
- [ ] Tag still points to the intended commit.

Example:

```bash
git tag -a v<VERSION> -m "AegisRun v<VERSION>"
git push origin v<VERSION>
```

If a workflow creates the tag with `GITHUB_TOKEN` and the tag-triggered Release workflow does not fire, use the supported `workflow_dispatch` path on the existing tag.

## 7. Distribution verification

### Source / GitHub

## 8. Deployment preparation

For a real staging/production deployment:

- [ ] DB backup created and identified.
- [ ] current image digests recorded.
- [ ] current migration version recorded.
- [ ] rollback target recorded.
- [ ] real OIDC configured.
- [ ] DB TLS configured.
- [ ] CORS configured.
- [ ] trusted-proxy/client-IP topology verified.
- [ ] Alertmanager/monitoring endpoints configured.
- [ ] backup restore procedure tested within policy window.

## 9. Production rollout

- [ ] candidate image digests resolved from published release.
- [ ] migration Job succeeds.
- [ ] rollout succeeds.
- [ ] `/health` returns expected version.
- [ ] `/ready` is healthy.
- [ ] metrics/SLO dashboards normal.
- [ ] canary/smoke checks pass.
- [ ] monitoring window completed.
- [ ] no new critical/high security regression identified.

## 10. Rollback evidence

- [ ] rollback playbook accessible.
- [ ] operator/on-call ownership established.
